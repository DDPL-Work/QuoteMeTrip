Prepared from the Troublefree Holiday preliminary scope dated 19 September 2026.
1. Project Overview
Troublefree Holiday is planned as a two-sided travel marketplace and quotation platform connecting Travellers with
tourism Agencies. Travellers create route-based travel requests and Agencies respond with quotations. An Admin interface
manages agency approval, memberships, requests, jobs, reporting and operational activities.
The platform consists of three principal interfaces: Traveller, Agency and Admin. The source scope defines a route-first
planning process in which route, distance, travel time and recommended days are calculated before the detailed request
form is completed.

3. Proposed System Architecture
• React.js presentation layer with separate Traveller, Agency and Admin application areas.
• Node.js/Express.js API layer providing authentication, authorization, business rules and integrations.
• MySQL relational database with normalized entities, foreign keys, indexes and transaction support.
• Integration layer for maps, routing, weather, email, SMS, Firebase, payment, e-signature and AI services.
• Production deployment through Nginx reverse proxy, HTTPS, Node process management and environment-specific
configuration.

25. Core End-to-End Workflow
1. Traveller logs in.
2. Traveller selects route on the map.
3. System calculates route, distance, estimated travel time and recommended days.
4. Traveller completes the detailed travel request.
5. System identifies relevant active agencies.
6. Agencies receive request notifications.
7. Agency reviews request and prepares quotation.
8. Traveller receives and reviews quotation.
9. Traveller and Agency communicate through the platform.
10. Contact information remains filtered before quotation acceptance.
11. Traveller accepts quotation.
12. System creates/updates the accepted job record and reveals contact information according to the defined workflow.
13. Admin can monitor the request/job and membership/commission status.
14. After service completion, Traveller receives a rating request.

• Password hashing using a current secure hashing algorithm.
• Role-based authorization enforced at API level.
• Request validation and sanitization.
• Parameterized SQL/ORM protections.
• Rate limiting on sensitive endpoints.
• Secure file-upload validation.
• HTTPS in production.
• Environment variables/secrets for credentials.
• Audit logging for sensitive Admin actions.
• Database transactions for critical state changes.
• Payment webhook signature/verification where supported.
